# Система правил и промптов для FoodTech

Создана система из 24 правил и 11 RTCF-шаблонов для учебного модуля заказов
готового питания. Правила применены к генерации кода, а результат проверен
на реальных запусках. Основной модуль проходит 41 тест; отдельная функция
после подключения правил проходит все 15 общих проверок.

## Шаг 1 Проект и стек

FoodTech — проект заказа готовых наборов здорового питания на день или неделю.
Аудитория 25–45 лет, бюджет ограничен, срок будущего MVP — три месяца.
Контекст взят из всех трёх текстовых файлов в исходной папке. Для ДЗ1/ДЗ2
выбран небольшой доменный модуль; создание целого мобильного приложения
не входит в эти задания.

Технологический стек: Python 3.12, стандартные dataclasses, datetime, json,
unittest. Нет фреймворка, БД и внешних библиотек: модуль изолирован от транспорта.
В дальнейшем его можно подключить к API без изменения формулы расчёта.
AI-инструмент — локальный Codex в уже установленном desktop-приложении.

```text
foodtech_demo/
  AGENTS.md
  demo.py
  foodtech/
    __init__.py
    pricing.py
    orders.py
  tests/
    __init__.py
    test_pricing.py
    test_orders.py
```

### Архитектура и стандарты

- `pricing.py`: чистая функция суммирования цен и доставки в копейках.
- `orders.py`: валидация заказа и котировка на 1 или 7 дней.
- `demo.py`: фиксированный пример, вывод JSON; без пользовательских данных.
- `tests/`: бизнес-сценарии и граничные условия, без внешней сети.

Публичные функции имеют типы и docstring. Деньги — целые копейки; bool,
float, отрицательные цены и доставка запрещены. Количество положительно,
заказ непустой, длительность 1/7 дней. Первая доставка не ранее чем через
два календарных дня от переданного today. Коллекции не изменяются.
Некорректный тип приводит к TypeError, недопустимое значение — к ValueError.
Правила установлены как проверяемые условия, а не как пожелания «писать хорошо».

## Шаг 2 Проектные правила

[rules.md](rules.md) содержит 24 пронумерованных правила в разделах Role,
Context, Style, Constraints и Format, включая пять явных запретов.
Файл предназначен для Codex. Идентичная рабочая копия —
[foodtech_demo/AGENTS.md](../foodtech_demo/AGENTS.md).

В текущей сессии правила подключены явным чтением файла перед второй
генерацией; автоподхват новой инструкционной папки в уже работающем чате
не предполагается. Для новой сессии нужно открыть `foodtech_demo` как проект:
Codex читает AGENTS.md перед работой согласно
[официальной документации](https://learn.chatgpt.com/docs/agent-configuration/agents-md).
Не используется неподдерживаемое предположение, что Codex автоматически
читает `.cursorrules`; исходное задание разрешает эквивалентный инструктаж
для выбранного агента.

## Шаг 3 Библиотека шаблонов

[prompt_templates.md](prompt_templates.md) включает 11 шаблонов и 11 примеров
с заполненными Role, Task, Context, Format. Первые пять покрывают все
обязательные сценарии: генерацию, рефакторинг, тесты, исправление бага,
декомпозицию. Дополнительные шаблоны покрывают ресерч конкурентов, SWOT,
ТЗ и три сценария из исходных текстовых файлов.

## Шаг 4 Последовательная цепочка

[prompt_methodology.md](prompt_methodology.md) описывает выполненную цепочку

использует артефакты предыдущего: контракт → реализация → проверка.

## Шаг 5 Проверка правил

[testing.md](testing.md) содержит сырой код до/после, общую спецификацию,
результаты одного набора тестов, вывод и ограничения сравнения.
Исходный вариант прошёл 8/15, после правил — 15/15.
Это последовательный пример в одной сессии; он не доказывает универсальную
величину влияния правил для всех задач и моделей.
