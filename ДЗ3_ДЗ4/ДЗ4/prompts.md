# Постановки, использованные при разработке

Инструмент: Codex; Sites — подготовка и публикация статического frontend.
Разработка идёт от ТЗ ДЗ3. Тексты ниже фиксируют рабочие RTCF-постановки
для этапов генерации и проверки; пользовательский запрос показан отдельно.

## Пользовательские запросы

«а теперь дополнительно выполни ДЗ3 и ДЗ4 согласно всем требованиям».
После подготовки: «запусти мне этот сайт, покажи работоспособность».
Создание GitHub-репозитория и загрузка материалов отдельно разрешены пользователем.

## P01 — структура и стек

Role: frontend-разработчик FoodTech.
Task: Создай React/Vite-проект с Pico CSS по техническому заданию ДЗ3.
Context: Адаптируй правила ДЗ2: ES modules, неизменяемый state, деньги целыми
копейками, today+2, периоды 1/7, доставка один раз, готовые фиксированные меню.
Format: package.json, lock, Vite config, AGENTS.md, src/components, src/domain,
src/data, public/catalog.json и README с запуском.

## P02 — интерфейс и состояния

Role: разработчик адаптивного UI.
Task: Реализуй выбранную концепцию 01, каталог, фильтры, диалог состава,
корзину и демооформление.
Context: 4 учебных рациона; desktop/cart справа, mobile/одна колонка; отсутствие
реальных платежей и персональных полей. Покажи loading, error, empty, success.
Format: Переиспользуемые React-компоненты, отдельные доменные helpers и mock API,
hash-маршруты каталога, оформления, успеха и гостевого кабинета.

## P03 — тестирование

Role: инженер по тестированию.
Task: Проверь ключевые действия пользователя и негативные ветки.
Context: Testing Library/Vitest, не сравнение внутренних деталей React.
Расчёт с несколькими позициями и неделей, пустая корзина, количество 9,
переход года, ранняя/пустая/несуществующая дата, невалидный каталог,
фильтрация, повтор запроса, ошибки 401/недоступности, двойное нажатие.
Format: Исполняемые unit/component tests и машиночитаемый результат.

## P04 — браузерная отладка

Role: UI-инженер.
Task: Проверь работающий сайт, исправь наблюдаемые дефекты.
Context: Пройти меню → корзина → 7 дней → дата/интервал → демоподтверждение;
проверить пустую дату и ошибки API; проверить Escape и возврат фокуса;
ширины 320, 375, 768, 1440; сохранить реальные скриншоты и ошибки консоли.
Format: Наблюдение → причина → конкретное исправление → повторная проверка.

## P05 — оптимизация и финальная проверка

Role: ревьюер frontend.
Task: Сопоставь FR01–20 с кодом и тестами, проверь сборку и размер.
Context: UI-библиотека Pico CSS, собственные SVG без внешних загрузок,
API-адаптер проверяет входные данные, расчёт вынесен из JSX, один Cart для
каталога и оформления. Не добавляй backend ради демонстрации.
Format: Отчёт development_report.md, команды в README, ZIP и GitHub с исходниками,
документами, тестами и скриншотами, без node_modules/секретов.
