# Проверка и согласование ТЗ

Проверка выполнена Codex как AI-ревью документа и реализации. Это не
независимая экспертная оценка и не пользовательское исследование.

## Запрос на проверку

«Сопоставь исходную FoodTech-идею, три UI-концепции, пользовательские пути,
story map, Given/When/Then и ТЗ. Найди противоречия, непроверяемые формулировки,
пропущенные ошибки и функции вне MVP. Для каждой Must-истории укажи требования,
компонент и способ приёмки. Не выдавай Mock-функции за production backend».

## Результаты и решения

| Потенциальная неоднозначность | Принятое уточнение |
|---|---|
| Состав готового рациона против настройки ингредиентов | Меню фиксировано, ингредиенты и аллергены только для просмотра |
| Цена за день против цены недельного заказа | Карточка за день, итог Σ(цена × количество) × 1/7 + доставка |
| Доставка за каждый день или за заказ | В учебной модели 150 ₽ один раз; реальная логистика вне frontend |
| Реальный заказ против демонстрации | Отдельное согласие, отсутствие платёжных/адресных полей, явное подтверждение demo |
| Кабинет требует backend | Гостевой экран и обработка 401; полноценный кабинет Should |
| Сохранение корзины между сессиями | Текущая память вкладки; восстановление после reload — Should US09 |
| Минимальная дата зависит от времени и часового пояса | Два календарных дня в локальной дате браузера; тест перехода года |
| Приоритеты развития выглядят как обязательства текущего MVP | US01–08 Must реализованы; US09–14 явно вынесены в последующие релизы |
| Пустой фильтр и пустой каталог смешаны | Отдельные сообщения; сброс фильтра и запрет пустого оформления |
| НФТ «удобный/быстрый» нельзя принять | Ширины 320/375/768/1440, цель 44 px, контраст, gzip-лимит, фокус и точные расчёты |
| Возраст и сценарии персон в первой версии идеи расходились с картой историй | Согласованы Анна 29 лет/первый день и Илья 37 лет/неделя во всех документах |

## Трассировка Must-историй

| История | Требования | Реализация | Подтверждение приёмки |
|---|---|---|---|
| US01 каталог/фильтр | FR01–04 | App, ProductCard, api | loading, четыре карточки, фильтр, empty, reset: component tests; четыре viewport |
| US02 состав | FR06–07 | MenuDialog | Component test; браузерное закрытие Escape и возврат фокуса |
| US03 корзина | FR08–09,11–12 | Cart, updateCart, totals | Пустая корзина, лимит, удаление, пересчёт: unit и component tests |
| US04 период | FR10–11 | App, Cart, totals | Два периода, неверный период, единая доставка: unit/component tests |
| US05 доставка | FR13–15 | Checkout, validateDelivery | Пустая, ранняя, граничная и несуществующая дата: unit/component tests; браузер |
| US06 подтверждение | FR16–18 | Checkout, App, submitDemoOrder | Согласие, двойная отправка, успех/очистка: component tests; скриншот успеха |
| US07 ошибки | FR05,19 | App, Checkout, api | Повтор каталога, неудачная отправка с сохранением: component tests; скриншоты |
| US08 гостевой режим | FR20 | App /account, Checkout 401 | Component test 401; браузерный гостевой экран и сохранённая корзина |

Все 20 FR покрыты Must-историями. Каждая текущая и будущая история имеет
позитивный и негативный Given/When/Then. Три основных функции для зачёта
(каталог, корзина, оформление) реализованы вместе с просмотром меню.

## Проверка комплектности ДЗ3

Идея и аудитория — project_description.md; три визуально разных результата
Text-to-UI в HTML/CSS — ui_concepts; выбор и компромиссы — ui_description.md;
карта историй и приоритеты — user_stories.md; два happy path и ветки ошибок —
user_journeys.md; критерии Given/When/Then и минимум три типа ошибок — там же
и в ТЗ. Финальный этап проверки и упаковки подтверждён этим документом,
README и репозиторием. Исходные файлы задания не изменены.
