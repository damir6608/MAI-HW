# Карта историй и критерии приёмки

## Персоны и границы

Анна, 29 лет, офисный специалист: хочет быстро выбрать готовое питание,
видеть состав и окончательную сумму. Илья, 37 лет, занятой родитель:
планирует питание на неделю и выбирает удобную первую доставку.
Это проектные персоны, а не результаты проведённых интервью.

## Backbone story map

| Этап пути | Must — текущий MVP | Should — следующий релиз | Nice — после проверки гипотез |
|---|---|---|---|
| Найти питание | US01 каталог и фильтр; US07 повтор запроса | US09 сохранённый фильтр | US12 сравнение рационов |
| Изучить меню | US02 блюда, БЖУ, аллергены | US10 избранное | US13 расширенные фото блюд |
| Собрать заказ | US03 корзина; US04 день/неделя | US09 восстановление корзины | US12 сравнение стоимости |
| Выбрать доставку | US05 дата и интервал | US11 несколько адресов после появления backend | US14 календарь доставки |
| Завершить | US06 демоподтверждение; US08 гостевое состояние | US10 авторизованный кабинет | US14 напоминания |

Should/Nice обозначают развитие продукта, в код ДЗ4 не входят. Полноценный
backend, реальные платежи и авторизация вынесены за границы учебного frontend.

## Must: истории и Given/When/Then

### US01 — найти подходящий рацион (Must, FR01–04)

Я как, занятый покупатель, хочу отфильтровать готовые рационы по типу питания,
чтобы быстро сравнить подходящие предложения.

```gherkin
Scenario: Каталог и фильтр
  Given каталог из четырёх валидных рационов загружен
  When пользователь выбирает «Растительные»
  Then показан только растительный рацион с названием, калориями, меню и ценой за день
  And выбранный фильтр имеет aria-pressed=true
Scenario: Нет результатов
  Given каталог содержит только сбалансированный рацион
  When пользователь выбирает «Растительные»
  Then показано «Нет рационов по этому фильтру»
  When пользователь нажимает «Все рационы» в пустом состоянии
  Then снова показан полный каталог
```

### US02 — узнать состав (Must, FR06–07)

Я как, покупатель, хочу открыть меню и аллергены рациона, чтобы принять
информированное решение о выборе готового набора.

```gherkin
Scenario: Открытие меню
  Given карточка «Баланс на каждый день» доступна
  When пользователь нажимает «Смотреть меню»
  Then открыт диалог с названием, блюдами, БЖУ, ингредиентами и аллергенами
  And фокус находится внутри диалога
Scenario: Отказ от выбора
  Given диалог открыт, а корзина пуста
  When пользователь нажимает Escape или «Закрыть меню»
  Then диалог закрывается и фокус возвращается к кнопке открытия
  And корзина остаётся пустой
```

### US03 — собрать и изменить корзину (Must, FR08–09, FR11–12)

Я как, покупатель, хочу добавить и изменить количество рационов, чтобы
заказать нужное число готовых наборов.

```gherkin
Scenario: Пересчёт количества
  Given выбран один день и корзина пуста
  When пользователь добавляет рацион по 900 рублей и нажимает «+»
  Then количество равно двум, рационы стоят 1800 рублей, доставка 150 рублей
  And итог равен 1950 рублей
Scenario: Пустая корзина
  Given в корзине одна единица рациона
  When пользователь нажимает «−»
  Then позиция удаляется, итог равен нулю, оформление недоступно
  And прямая ссылка на оформление показывает приглашение выбрать рацион
Scenario: Предельное количество
  Given количество позиции равно девяти
  When пользователь пытается увеличить количество
  Then кнопка «+» недоступна, количество не превышает девять
```

### US04 — запланировать период (Must, FR10–11)

Я как, Илья, хочу выбрать питание на день или семь дней, чтобы увидеть
стоимость на весь планируемый период.

```gherkin
Scenario: Неделя
  Given в корзине одна единица по 900 рублей и выбран один день
  When пользователь выбирает «7 дней»
  Then рационы стоят 6300 рублей и итог равен 6450 рублей
  And доставка добавлена только один раз за заказ
Scenario: Недопустимый период на границе домена
  Given передано значение days=2, строка «7» или логическое true
  When вызывается расчёт суммы
  Then значение отклоняется с RangeError и сумма не вычисляется
```

### US05 — выбрать первую доставку (Must, FR13–15)

Я как, покупатель, хочу выбрать допустимую дату и интервал первой доставки,
чтобы понимать, когда ожидается готовое питание.

```gherkin
Scenario: Допустимая дата
  Given сегодня 12 октября 2026 года и корзина непуста
  When пользователь выбирает 14 октября и интервал 14:00–18:00
  Then дата проходит проверку, а выбранный интервал сохраняется в заказе
Scenario: Неверная дата
  Given корзина непуста
  When пользователь отправляет форму с пустой датой или датой раньше today+2
  Then показана понятная ошибка и Mock API не вызывается
  And корзина и введённые значения сохраняются
Scenario: Несуществующий день
  Given в доменную проверку передана дата 2027-02-30
  When выполняется проверка даты
  Then возвращается «Укажите корректную дату»
```

### US06 — получить подтверждение (Must, FR16–18)

Я как, покупатель, хочу подтвердить демонстрационный заказ и увидеть его
результат, чтобы проверить весь путь оформления без реальной оплаты.

```gherkin
Scenario: Успешное оформление
  Given корзина непуста, дата допустима и подтверждён демонстрационный режим
  When пользователь отправляет форму и Mock API отвечает успешно
  Then показаны номер, дата, интервал, период и итог
  And явно написано, что оплата не списывалась и реальная доставка не оформлена
  And корзина очищается
Scenario: Нет подтверждения режима
  Given дата допустима, но флажок демонстрационного режима не установлен
  When пользователь отправляет форму
  Then показана ошибка, а Mock API не вызывается
Scenario: Повторное нажатие
  Given первый запрос ещё выполняется
  When пользователь повторно нажимает подтверждение
  Then кнопка недоступна и вызван только один Mock-запрос
```

### US07 — восстановиться после ошибки (Must, FR05, FR19)

Я как, покупатель, хочу повторить неудачный запрос без потери выбора, чтобы
завершить действие после временного сбоя.

```gherkin
Scenario: Повтор каталога
  Given первый запрос каталога завершился ошибкой
  When пользователь нажимает «Повторить загрузку» и следующий запрос успешен
  Then каталог отображается без перезагрузки страницы
Scenario: Сбой оформления
  Given корзина и допустимая форма заполнены
  When Mock API оформления отвечает ошибкой
  Then показано «Не удалось оформить демозаказ. Повторите попытку»
  And дата, интервал, согласие и корзина сохраняются, кнопка снова доступна
  And успешное подтверждение не показывается
```

### US08 — понять гостевой доступ (Must, FR20)

Я как, посетитель без аккаунта, хочу понимать границы гостевой демоверсии,
чтобы продолжить доступные действия без ложного обещания входа.

```gherkin
Scenario: Открытие кабинета
  Given посетитель находится в демоверсии
  When он открывает «Личный кабинет»
  Then показано гостевое состояние и ссылка «Вернуться к меню»
  And выбранная корзина сохраняется
Scenario: Ответ 401
  Given включён сценарий demo=unauthorized и форма заполнена
  When отправка возвращает 401
  Then показано сообщение о недоступности кабинета в демоверсии
  And корзина и форма сохраняются, успешный заказ не создаётся
```

## Следующие релизы: истории с критериями

| ID / приоритет | История | Позитивный Given/When/Then | Негативный Given/When/Then |
|---|---|---|---|
| US09 Should | Я как, возвращающийся посетитель, хочу восстановить выбор, чтобы продолжить заказ | Given сохранён валидный выбор; When открыта вкладка; Then восстановлены фильтр и корзина | Given повреждены сохранённые данные; When открыта вкладка; Then показан чистый каталог без падения |
| US10 Should | Я как, клиент, хочу видеть избранное в кабинете, чтобы повторять выбор | Given есть backend и вход; When открыто избранное; Then видны сохранённые рационы | Given сессия истекла; When открыт кабинет; Then предложен вход без потери корзины |
| US11 Should | Я как, клиент, хочу сохранить несколько адресов, чтобы выбирать место доставки | Given выполнен вход; When выбран поддерживаемый адрес; Then он связан с заказом | Given адрес вне зоны; When он выбран; Then оформление блокируется с объяснением |
| US12 Nice | Я как, покупатель, хочу сравнить рационы рядом, чтобы оценить стоимость и меню | Given выбраны два рациона; When открыто сравнение; Then видны одинаковые поля и единицы | Given выбран один рацион; When открыто сравнение; Then предложено выбрать второй |
| US13 Nice | Я как, покупатель, хочу видеть фото блюд, чтобы оценить подачу | Given доступны проверенные изображения; When открыто меню; Then показаны фото с alt | Given изображение недоступно; When открыто меню; Then остаётся текст и заглушка |
| US14 Nice | Я как, клиент, хочу видеть календарь и напоминание, чтобы помнить о доставке | Given есть подтверждённый реальный заказ и разрешение на уведомления; When наступает срок; Then отображается напоминание | Given разрешения нет; When наступает срок; Then внешнее уведомление не отправляется |

Критерии US09–US14 задают будущую приёмку и не являются заявлением об
их реализации. Продуктовые ограничения и перечень функций текущей версии — в ТЗ.

## Нумерованный перечень историй

1. US01 — Я как, занятый покупатель, хочу отфильтровать готовые рационы, чтобы сравнить подходящие предложения.
2. US02 — Я как, покупатель, хочу открыть меню и аллергены, чтобы принять информированное решение.
3. US03 — Я как, покупатель, хочу изменить количество рационов, чтобы заказать нужное число наборов.
4. US04 — Я как, Илья, хочу выбрать питание на 1/7 дней, чтобы увидеть стоимость за период.
5. US05 — Я как, покупатель, хочу выбрать дату и интервал, чтобы понимать время первой доставки.
6. US06 — Я как, покупатель, хочу подтвердить демозаказ, чтобы проверить оформление без оплаты.
7. US07 — Я как, покупатель, хочу повторить запрос, чтобы восстановиться после сбоя без потери выбора.
8. US08 — Я как, посетитель без аккаунта, хочу понимать границы демоверсии, чтобы продолжить доступные действия.
9. US09 — Я как, возвращающийся посетитель, хочу восстановить выбор, чтобы продолжить заказ.
10. US10 — Я как, клиент, хочу видеть избранное, чтобы повторять выбор.
11. US11 — Я как, клиент, хочу сохранять адреса, чтобы выбирать место доставки.
12. US12 — Я как, покупатель, хочу сравнить рационы рядом, чтобы оценить стоимость и меню.
13. US13 — Я как, покупатель, хочу видеть фото блюд, чтобы оценить подачу.
14. US14 — Я как, клиент, хочу видеть календарь и напоминания, чтобы помнить о доставке.

Критерии Given/When/Then каждой истории приведены выше: отдельные сценарии
