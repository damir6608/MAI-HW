# Happy Path — формат исходного промпта

Путь занятого покупателя 25–45 лет. Границы ДЗ4: frontend с Mock-оплатой и
доставкой. Нет реальных уведомлений, списаний, адресов или сложной настройки.
Бюджет ограничен, горизонт продуктового MVP — три месяца.

1. **Обнаружение и первая точка входа**
   - User goal: Понять, подходит ли сервис готового питания.
   - Actions: Открывает сайт, читает описание готовых наборов на день/неделю.
   - Touchpoints: Вводный экран FoodTech, ссылка «Меню рационов».
   - Emotions: Интерес.
   - Pain points: Недостаточно информации о качестве еды при первом знакомстве.
   - Improvements: Добавить проверенные отзывы и реальные фото производства после исследования.
2. **Первое знакомство с условиями**
   - User goal: Понять условия заказа до выбора рациона.
   - Actions: Читает пояснение «без подписки», срок первой доставки и отметку демоверсии.
   - Touchpoints: Вводный экран, сводка заказа, подпись демонстрационного проекта.
   - Emotions: Внимание.
   - Pain points: Неясно, чем демоверсия отличается от действующего сервиса.
   - Improvements: В следующем реальном продукте добавить короткий онбординг и необязательный запрос уведомлений после объяснения пользы.
3. **Выбор типа питания**
   - User goal: Найти подходящий фиксированный рацион.
   - Actions: Нажимает «Растительные» или «Сбалансированные», сравнивает карточки.
   - Touchpoints: Фильтры, калорийность, цена за день, названия рационов.
   - Emotions: Сосредоточенность.
   - Pain points: Тип питания не объясняет все индивидуальные предпочтения.
   - Improvements: Добавить сравнение двух рационов без кастомизации состава.
4. **Детальный просмотр меню**
   - User goal: Проверить блюда, ингредиенты и аллергены.
   - Actions: Открывает «Смотреть меню», читает состав, закрывает диалог.
   - Touchpoints: Диалог меню, БЖУ, аллергены, Escape/кнопка закрытия.
   - Emotions: Осторожность.
   - Pain points: По текстовому примеру трудно оценить размер порций.
   - Improvements: Добавить проверенные фото блюд и точную массу порций.
5. **Корзина и период**
   - User goal: Увидеть окончательную стоимость выбранного питания.
   - Actions: Добавляет рацион, выбирает 1/7 дней, меняет количество, сверяет доставку и итог.
   - Touchpoints: Кнопка добавления, переключатель периода, +/−, разбивка суммы.
   - Emotions: Контроль.
   - Pain points: Недельная сумма заметно больше дневной цены карточки.
   - Improvements: Добавить сохранение корзины между сессиями и сравнение стоимости за период.
6. **Первая доставка и демонстрационное подтверждение**
   - User goal: Проверить полный путь заказа с допустимой датой и интервалом.
   - Actions: Выбирает дату не раньше today+2, интервал, подтверждает деморежим, отправляет форму и сверяет результат.
   - Touchpoints: Форма доставки, согласие, pending-кнопка, номер и итог демозаказа.
   - Emotions: Спокойствие.
   - Pain points: Результат не сохраняется после перезагрузки вкладки.
   - Improvements: После появления backend добавить реальную оплату, историю заказов и уведомления с отдельным согласием.

Этапы:

- Обнаружение и первая точка входа.
- Первое знакомство с условиями.
- Выбор типа питания.
- Детальный просмотр меню.
- Корзина и период.
- Первая доставка и демонстрационное подтверждение.
