Ты — опытный руководитель продукта в FoodTech. Спроектируй пользовательский путь (только Happy Path) для MVP мобильного приложения по заказу здорового питания.

Контекст: ЦА 25–45 лет, бюджет ограничен, срок разработки MVP — 3 месяца. Приложение позволяет выбрать готовый набор блюд на день/неделю, оплатить и оформить доставку. Сложная кастомизация, собственная логистика и AI-рекомендации не входят в MVP.

Ограничения: Только критически важные для MVP функции. Не более 10 этапов. Никаких общих фраз и оптимистичных оценок.

Каждый этап должен содержать следующие поля (строго по шаблону):
User goal (цель пользователя на этом этапе)
Actions (конкретные действия пользователя)
Touchpoints (точки взаимодействия: экраны, кнопки, уведомления, курьер, и т.д.)
Emotions (реалистичная эмоция, одно слово или эмодзи)
Pain points (болевые точки, даже на идеальном пути)
Improvements (возможные улучшения для следующих версий, без привязки к текущему бюджету)

Пример желаемого стиля для одного этапа:
Знакомство с приложением и первое впечатление
User goal: Понять, подходит ли сервис для моих пищевых предпочтений.
Actions: Открывает App Store, читает описание, смотрит 3 скриншота, проверяет рейтинг.
Touchpoints: Карточка приложения в сторе, скриншоты с примерами меню.
Emotions: Любопытство, лёгкий скепсис (если мало отзывов).
Pain points: Непонятно, есть ли веганские опции; скриншоты выглядят слишком «стоково».
Improvements: Добавить видео с реальными блюдами, вынести в описание списком типы рационов.

Формат ответа: нумерованный список этапов (начиная с 1), в конце отдельно перечисли названия всех этапов в виде маркированного списка.
